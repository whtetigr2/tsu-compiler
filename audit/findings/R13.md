# R13 -- Layers / overlays / composite (Wave 4)

**Method:** read `demo/layers.py`'s own module docstring (which states the
ancestral-vs-joint distinction as a "MANDATORY CAVEAT... must be stated
plainly, never glossed as 'the joint distribution'") and then, separately,
grepped and read every ON-SCREEN string the LAYERS panel and composite view
actually render, to determine whether that mandatory caveat -- which exists

the code. Then verified the cross-layer-rules-are-soft-nudges claim and the
`composite_base_grid` residual against the code that enforces them.

## The ancestral/directed factorization: correctly understood in the code, never stated on screen

`demo/layers.py:24-34`, the module's own "MANDATORY CAVEAT": *"stacking
samples p(layer1) * p(layer2 | layer1), a DIRECTED / ANCESTRAL
factorization, NOT the joint Boltzmann distribution over both layers at
once... this is a deliberate modelling choice, the same one Extropic's
Denoising Thermodynamic Models make... and it must be stated plainly, never
glossed as 'the joint distribution.'"* This is architecturally correct and
independently verifiable from the mechanism itself: `bias_patch`
(`demo/layers.py:63-160`) only ever mutates `biases`/`offset` on a fresh
`SamplingProgram` derived from `demo/receipts/elev_band`'s own compiled
program (`:105-108`'s own docstring: *"Only `biases` (and `offset`...) ever
change. `nodes`, `edges`, `weights` (couplings), and `blocks` are returned
bit-for-bit identical"*) -- each band is sampled as its own, independent
Boltzmann draw from a program conditioned (via biases only) on the layer
below's already-fixed decode, exactly the sequential/ancestral structure the
docstring claims, never a joint two-layer energy function.

**Grepped every on-screen string in `demo/lattice_app.py` and
`demo/explainer.py` for this claim, by name or by substance
(`"ancestral"`, `"joint Boltzmann"`, `"DIRECTED"`, `"p(base)"`,
`"factorization"`, `"single Boltzmann"`, `"one Boltzmann"`) -- zero
matches, anywhere, in either file.** The single occurrence of
`"p(base)*p(band|base)"` in `demo/lattice_app.py` (`:3934`) is inside a
**code comment** explaining to a future maintainer why `composite_base_grid`
must be used instead of `self.last_valid_grid` -- it is never assigned to
any Tk `Label`/caption string, so no viewer of the running app ever sees it.
The composite view's own on-screen text (`_refresh_layer_view`'s composite
branch, `:3908-3976`; `_refresh_composite_readout`, `:3826-3848`) covers two
different, real disclosures -- which band's base snapshot the terrain came
from (the staleness note, `:3959-3973`) and the measured monotonicity
violation rate (`:3839-3848`, verified next) -- but at no point states that
the composite as a whole is not one joint sample of a combined base+bands
model, the specific misreading `layers.py`'s own docstring says must never
be allowed to happen by omission.

## Findings

### Important

**The composite view's own "MANDATORY CAVEAT" (layers.py's own words for
its severity) is enforced in the sampling code but never surfaces on the
screen where a composite is actually shown to a viewer.**
`demo/layers.py:24-34` (quoted above). **Concrete failure scenario:** a
viewer opens the LAYERS panel, selects "composite," sees one coherent-looking
elevation-shaded world image (`render_elevation_world_image`, `:3955`) built
from base + three independently-sampled bands, reads the on-screen staleness
note about WHICH base snapshot it used, reads the on-screen monotonicity
readout about how often adjacent bands disagree -- and, having been told
about those two specific caveats, reasonably concludes that is the complete
list of ways "composite" differs from a single physical draw. Nothing on
screen tells them the more fundamental fact: even a perfectly fresh,
perfectly monotone composite is a chain of independently-sampled conditional
draws, never a joint sample of one combined energy function, so questions
like "what is the joint probability of this exact base+band0+band1+band2
configuration" cannot be answered by treating the displayed composite as
one physical draw the way DECODED WORLD's base-only image can be. This is
precisely the "domain vocabulary borrowed from a context that may not
transfer" risk the audit brief calls out for this wave, and the project's
own source code identifies the exact failure mode ("never glossed as 'the
joint distribution'") without ever putting the corrective sentence where a
viewer -- as opposed to a maintainer reading `layers.py`'s docstring -- would
see it. **What was checked:** full read of `demo/layers.py`'s docstring and
mechanism; grep of every on-screen string in `lattice_app.py`/`explainer.py`
for the claim or its substance (zero hits outside one code comment); read of
every composite-adjacent Label/caption construction site
(`_refresh_composite_readout:3826-3848`, `_refresh_layer_view` composite
branch `:3908-3976`) to confirm neither states it by other wording either.
**Recommended scope for Phase F (not performed here):** add one line to
either `_refresh_composite_readout`'s label or the composite branch's
`world_status_label` text stating the ancestral/directed nature of the
stack in plain language (e.g. "each layer is its own independent sample,
conditioned on the layer below -- not one joint draw of a combined model"),
reusing `layers.py`'s own wording rather than inventing new phrasing that
could drift from it.

## The known residual: `composite_base_grid` -- verified already disclosed, not a new finding

`self.composite_base_grid` (`demo/lattice_app.py:2165`, set in
`_on_band_regenerated:4368`) is a single app-wide value, overwritten
unconditionally by whichever band regenerates most recently -- confirmed
directly from the assignment site: there is exactly one attribute, no
per-band dict of base snapshots. The composite branch's own code comment
(`:3939-3953`, "NOTE (fix-round-3, re-review residual)") states this
precisely, including that "claiming joint consistency across all three [is]
exactly the overclaim this whole review round was about" -- and, checked
independently against the actual rendered text rather than trusting the
comment's claim that it was fixed, `world_status_label`'s composite text
(`:3965-3973`) does say exactly this on screen: *"the OTHER bands may have
been conditioned on a DIFFERENT base draw (each band regenerates
independently; see COMPOSITE VALIDATION below for the cross-layer check)"*,
with `base_is_stale` (`:3959`) computed by direct `np.array_equal` against
`self.last_valid_grid`, not asserted. **Verdict: PASS (verified, not merely
inherited) -- this residual is a disclosed, named limitation with real,
correct on-screen text, not a live finding**, and is the reason R13's
Important finding above is scoped narrowly to the DIFFERENT, undisclosed
ancestral-factorization claim rather than re-filing this already-closed
item.

## Cross-layer rules as soft nudges, not guarantees: verified against the code that enforces them

`_refresh_composite_readout` (`:3826-3848`) computes `viol =
monotonicity_violations(band_decoded)` **live**, every time the composite
is (re)viewed, from `demo/elevation.py:50-68` -- confirmed this function
only ever appends to a list (detects), never mutates `bands` (no sort, no
clamp, no repair anywhere in its body) -- and displays: *"monotonicity
violations (band i+1 true where band i false): {n}/{slots} cell-transitions
({rate}%). DETECTED, not repaired -- band_patch's nudge is an encouragement,
never a hard constraint, so this can and does exceed 0%."* This is a live
measurement, not a hardcoded reference figure -- checked specifically
because the audit brief cites "~4.69%" as a known measured figure (traced to
`.superpowers/sdd/2026-09-01-lattice-layers-and-scope/task-4-7-report.md:25
-27`'s own calibration run, "STRENGTH=1.0 ... 8.32% -> 4.64%"), and the live
UI's number will differ session to session (different seeds, different
`alpha`/`OVERLAY_PIN_STRENGTH` if pinned) -- correctly so, since the code
never claims a fixed reference rate on screen, only ever the live one.
`band_patch` (`demo/elevation.py:71-123`) itself is confirmed, by reading
its arithmetic, to build a `strength`-scaled **bias** term (folded through
`bias_patch` into `biases` only, never into a hard constraint on the
sampled state) -- there is no code path from `band_patch`'s output to
anything that could force monotonicity, matching the "encouragement, never
a guarantee" framing exactly.

### What was tried and did not turn up a finding

- Checked whether `band_patch`'s "monotonicity is the DIRECTION-setting
  term" combination rule (`:109-120`, `base_factor` bounded to `[0.5, 1.5]`
  so it can only modulate magnitude, never flip `below_term`'s sign) could,
  for some base value, actually flip the encouragement's direction despite
  the docstring's claim it cannot -- re-derived the bound algebraically
  (`base_term in {-1, 0, 1}` for the three terrain values, so `base_factor
  = 1 + 0.5*base_term in {0.5, 1.0, 1.5}`, always strictly positive) --
  confirmed correct, no finding.
- Checked whether `bias_patch`'s `FieldCapExceeded` refusal
  (`demo/layers.py:110-114`, `:149-157`) is silently swallowed anywhere on
  the path from a band regenerate to the screen -- `_regenerate_band_async`
  (`:4320-4325`) catches `Exception` generically but re-raises it as a
  `band_regenerate_error` message surfaced to the log/status line, never
  swallowed. No finding.
- Checked whether the composite's elevation field itself
  (`thermometer_level`, `demo/elevation.py:41-47`) could silently repair a
  non-monotone band stack when computing the displayed LEVEL (e.g. by
  taking the highest contiguous prefix rather than a raw true-band count) --
  confirmed it is a bare `sum(1 for band in bands if band[cell] == 1)`, so a
  genuinely non-monotone cell (e.g. band0 false, band1 true, band2 false)
  reads as level 1 exactly as a naive count would, with no special-casing
  that would mask the violation `monotonicity_violations` reports
  separately. Both numbers are independently real, not reconciled to agree.
- Checked whether the base layer's own `p(x | valid)` framing
  (`demo/explainer.py:255-272`) could itself be read as implying "composite"
  is drawn the same way -- explainer.py's own text is scoped to "every world
  you see in DECODED WORLD," which is the base-layer-only view; it makes no
  claim about the LAYERS panel's composite pseudo-layer at all (the
  explainer window predates Task 7's LAYERS panel and was not updated to
  mention it -- an omission, not a misstatement, and not itself filed as a
  finding since explainer.py never claims composite is anything).
