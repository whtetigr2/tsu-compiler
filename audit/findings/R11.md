## Is the local field post-hoc reconstructed? Confirmed independently, from the arithmetic.

`demo/scope.py:283-289`:

```python
spins = 2.0 * draws_arr - 1.0                      # (n_draws, n_spins)
field = np.tile(biases, (n_draws, 1))
for k, (u, v) in enumerate(ising.edges):
    w = weights[k]
    field[:, u] += w * spins[:, v]
    field[:, v] += w * spins[:, u]
gamma = beta * field
```

`spins[:, v]` is read from `draws_arr` -- the FINAL recorded joint state of
each sample -- for every neighbour `v` of every node `u`, regardless of
whether `v` was updated before, after, or in the same colour-block as `u`
within that Gibbs sweep. This is unambiguous: the field used here is
reconstructed from the completed draw, not captured at the moment `u` was
actually resampled. **Confirmed independently from the arithmetic itself,
not merely by trusting the function's own docstring**, which makes the
identical claim (`scope.py:56-58`: *"THRML exposes no public API for the
local field at the moment a spin was actually flipped, so gamma_i here is
RECONSTRUCTED POST HOC from the final recorded joint draw"*) -- code and
comment agree, and the code is what was actually checked.

**Confirmed further from `thrml`'s own installed source
(`site-packages/thrml/block_sampling.py`) that this is a genuine, current
API limitation, not a historical one this project failed to work around:**
`sample_blocks` (`:337-376`) drives the whole chain through
`jax.lax.scan`-wrapped calls to `sample_single_block` (`:264-334`), which
computes each block's new state via
`sampler.sample(key, per_block_interactions, ..., all_interaction_states,
...)` and returns ONLY `(out_samples, out_sampler_state)` -- the
`all_interaction_states` array (which IS the true field/logit input to the
block's conditional, computed fresh from whichever neighbour values are
CURRENT at that exact point in the sweep) is a local variable, never
returned, never exposed via any Observer hook.
`AbstractConditionalSampler.sample`/`AbstractParametricConditionalSampler.compute_parameters`
(`conditional_samplers.py:23-56,74+`) is exactly where the true field is
computed, per-block, per-substep -- and its return value is likewise never
surfaced outside the sampler. The ONLY observation hook the public API
offers (`AbstractObserver`/`StateObserver`, `sample_with_observation`,
`block_sampling.py:422-501`) fires once per COMPLETED sample (after
`steps_per_sample` full sweeps), and observes only `state`, never the
per-block field that produced it. **This independently corroborates the
docstring's central factual claim: thrml genuinely exposes no public route
to the field at flip time**, at both the per-sample AND the per-block-update
granularity.

## The minimal experiment for a TRUE kernel-response curve

**What would have to be instrumented.** The true field is computed inside
`AbstractParametricConditionalSampler.compute_parameters`
(`thrml/conditional_samplers.py`), fed `all_interaction_states` --
built by `sample_single_block` (`block_sampling.py:295-311`) from
`global_state`, itself rebuilt from the CURRENT `state_free` at the start
of each colour-block's turn within `sample_blocks`'s per-`sampling_group`
loop (`block_sampling.py:366-375`). This is the one place in the whole
pipeline where "the field the kernel actually used" and "the block about
to be resampled from it" are both in scope at once.

**Does thrml expose it?** No -- confirmed above, independently, from
reading the actual source: neither `sample_single_block` nor
`AbstractConditionalSampler.sample`'s return type carries the field out,
and the only public observation hook (`AbstractObserver`) fires per
COMPLETED SAMPLE, not per block-update, and observes state only.

**The honest fallback / minimal experiment, in order of increasing
fidelity:**

1. **Composition, no thrml source changes, no `src/` changes:** wrap the
   real `AbstractConditionalSampler` used for the Ising blocks in a
   diagnostic subclass whose `sample`/`compute_parameters` computes the
   SAME field its parent would (it receives the identical
   `interactions`/`states` arguments thrml already threads through), records
   it, then delegates to the real implementation for the actual draw. This
   captures the true, per-block, per-substep field with NO reconstruction
   step and no dependence on thrml exposing anything new -- it is legal
   composition against thrml's existing public `AbstractConditionalSampler`
   interface. The obstacle is JAX-native: this whole loop is normally
   `jax.lax.scan`-compiled for speed, and a Python-side recording side
   effect cannot escape a `scan`/`jit` trace without either (a) using
   `jax.debug.callback`/`io_callback` to stream values out during
   tracing, or (b) abandoning `sample_with_observation`'s all-in-one scan
   and driving `sample_blocks` manually, one sweep (or even one
   colour-block) at a time, from an ordinary Python loop.
2. **Concretely, for a "minimal experiment" scale run (a handful of
   chains, hundreds of sweeps -- not production-scale sampling):** call
   `block_sampling.sample_single_block` directly per block per sweep in
   Python instead of via `sample_with_observation`, recomputing the same
   `global_state`-slicing thrml already does (via the already-public
   `block_state_to_global`) to independently verify the recorded field
   matches what the block's sampler was actually given, then record
   `(field, new_sample)` pairs BEFORE the state advances to the next
   block. This trades full-chain JIT fusion for genuine flip-time fidelity
   -- acceptable for a diagnostic run, not something to make the default
   sampling path (which correctly stays fully compiled for the production
   use this app otherwise needs).
3. **If neither is judged worth the engineering cost:** the current
   fallback (post-hoc reconstruction, fully disclosed on screen at three
   sites, correctly labelled REFERENCE ONLY, correctly stating that a
   reconstruction artifact and a genuine defect are indistinguishable from
   this plot alone) is the right honest fallback -- it is not a defect to
   leave the plot as it is; it would be a defect to claim it is anything
   more than what it is, which the current code does not do.

**Verdict: PASS.** The local field IS post-hoc reconstructed (independently
confirmed from the arithmetic and from thrml's own source, not merely
trusted from a docstring); this fact IS disclosed, accurately and
prominently, at three independent on-screen sites; the ~18-sigma deviation
and the staleness-hypothesis test are both real, both independently
located, and both accurately characterised in the code's own words. No
finding contradicts the brief's description of the known state; the
Minor finding above is a latent risk in a currently-nonexistent export
path, not a defect in what is shown today.
