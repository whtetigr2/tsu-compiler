## Independent re-verification of the two load-bearing citations

**1. `|J| <= 6.0` is Extropic-documented, not assumed.** Extracted
`2608.01615v1.pdf` page 22 myself and found, embedded in Fig. 12's own
axis-label text: `"0.3 0.5 0.75 1 1.5 2 3 6 (Z1) 10"` -- the figure
explicitly annotates the value **6** as **"(Z1)"**, i.e. the sweep marks
which of its nine swept caps is the actual Z1 hardware value, distinct
from the other eight studied purely numerically. Confirmed independently,
not copied from A3 or the controller's research.

**2. `|b| <= 6.0` has no documented numeric source.** Grepped both
extracted PDFs myself for every case-insensitive occurrence of
`hmax`/`h max`/`h_max`: exactly 2 hits, both in `2608.01615v1.pdf`
(pp.13, 20), both purely symbolic (`"|h| <= hmax"`, `"|hi| <= hmax"`) --
neither gives a number. `max_abs_coupling=6.0` is reused for `|b|` by
project-side symmetry with `|J|`, a choice the paper never makes or
endorses. Confirmed independently.

Both of these match `provenance.md`'s classification exactly. I am not
relaying that ledger uncritically -- these are my own extractions, run
fresh in this task, cited to the same page/line -- but the numbers agree,
which is itself worth stating plainly rather than silently re-deriving and
saying nothing.

## Independent re-verification: `node_budget`

Grepped both extracted PDFs myself:

- `2608.01615v1.pdf`, found at the exact string offset expected: *"the
  entire chip has ~250,000 nodes"* (p.5) -- verbatim match to
  `target.py:64`'s `quote` field, character for character including the
  tilde.
- `From One to One Billion...pdf`, Fig. 05 caption: *"The Z1 die: eight
  cores, 269,568 pbits, 215,904 coupling parameters, >50 MHz sampling
  rate, <1 W."* -- a different, more precise figure for what the SAME
  document later also calls, in prose, *"over a quarter million pbits"*
  (consistent with, but not equal to, the 250,000 the code uses).

Both are genuine, verbatim Extropic quotes for what both documents
describe as "the entire chip['s]" node count; they disagree with each
other by ~7.8%. `node_budget=250,000` is real and citable (not fabricated,
not merely conservative) -- but it tracks the older, rounder, less precise
of two disagreeing Extropic figures, and the code has no way to express
"documented, but contested by a more precise figure elsewhere" -- the
`Sourced.source` field is a single string (`"F-15"` or `"assumed"`), a
binary, not a spectrum.

## Findings

### Important

**I-9a (restates and independently re-confirms `provenance.md`'s P-3, does
not re-litigate its detail): `\|J\| <= 6.0` is disclaimed identically to
`\|b\| <= 6.0` at all six sites above, and this is now factually wrong for
`\|J\|`.** The plan's rule ("project assumptions must never be rendered in
the same visual language as documented silicon specifications") is
violated in the CONVERSE direction from every other finding in this
audit: a documented fact (`\|J\| <= 6.0`, citable to Fig. 12's "(Z1)"
annotation) is currently rendered with the SAME visual language
(`"(assumed limit)"` tag, identical prose disclaimer) as a genuine project
assumption (`\|b\| <= 6.0`). **Concrete failure scenario:** a viewer reading
`explainer.py`'s section 05 -- *"every place this app displays them says
so"* -- is told, in-app, that a single disclaimer reliably describes BOTH
caps everywhere; that claim about the app's own internal consistency was
true when both were unsourced and is now false in exactly the direction
that UNDERSELLS the project's own credibility (a real, citable hardware
fact is being told to a viewer as "not sourced"). **Severity note:**
classified Important rather than Critical because the failure direction is
underclaiming, not overclaiming -- no false claim of hardware-sourced
authority reaches a viewer; a real fact is merely hidden behind an
unnecessary caveat. **What was checked:** all six sites read directly (not
copied from provenance.md); `gates.json` for the small/l0/l1/l1_infeasible/
elev_band receipts checked to confirm `"assumed": true` for BOTH gates in
every one (grepped `demo/receipts/*/gates.json`). **Not performed (Phase F
candidate, schema change + six text edits, TDD as the plan requires):**
add `max_abs_bias: Sourced` to `TargetProfile` distinct from
`max_abs_coupling`, thread it through `gates.py`'s `field_cap` call, and
correct the five prose sites plus the VERIFICATION panel tag.
