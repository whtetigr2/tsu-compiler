# R15 -- Independent oracle tests (Wave 2)

**Method:** the plan requires a statistical criterion **stated before the
result is seen**. That criterion is written into
`audit/r15_oracle_comparison_check.py`'s own module docstring, reproduced
verbatim below, and was not edited after the script was first run --
the plan is explicit that a failure here is itself the finding, not
something to be tuned away.

## Pre-registered criterion (verbatim from the script, written before execution)

> A Pearson chi-square goodness-of-fit test, H0: the sampler's stationary
> distribution over the model's `2**n` states equals `exact_boltzmann`'s
> distribution. Expected counts = `N * exact_probs` (every expected count
> checked `>= 5`, the standard rule-of-thumb minimum for the chi-square
> approximation to be valid -- if not, `N` is increased, decided before
> running, not after seeing a failing result). Significance level
> `alpha = 0.01`. **PASS iff p >= alpha**, i.e. the observed sample counts
> are not so different from the exact distribution that they would occur by
> chance less than 1% of the time under a perfectly correct sampler.
>
> Sampler configuration: `tsu.backends.thrml_backend.sample` -- the SAME
> function `demo/lattice_app.py` imports as `thrml_sample` and calls from
> its own unclamped-tick worker -- at the app's own fixed constants for
> that path: `n_warmup=300`, `steps_per_sample=4`
> (`demo/lattice_app.py:118-119`), `n_chains=200` and `n_samples=50`
> (10,000 total draws; scaled up from the live app's own tiny per-tick
> `n_chains` so this single batch has enough draws for the chi-square
> approximation to be valid on an 8-state model -- the live app instead
> accumulates draws across many ticks). Seed=20260903, fixed before running.
>
> If this fails, the plan is explicit: that IS the finding. This script
> will not be re-run with different parameters to make it pass.

## Instance

The same deliberately asymmetric 3-spin model R3 used (reused rather than
inventing a new one): `edges=((0,1),(0,2),(1,2))`,
`weights=[-0.225,-0.05,0.125]`, `biases=[-0.625,0.05,-0.475]`,
`offset=0.9`, `beta=1.0`, lowered by the real `tsu.passes.lower.lower` and
built into a `SamplingProgram` via the real `analyse()`/`build_program()`
(3-colour chromatic blocks, non-bipartite -- chromatic block Gibbs is exact
for any proper colouring, not only a 2-colouring, so no mediation was
needed for this correctness test).

Rarest-state expected count at N=10,000: 275.15 (well above the chi-square
rule-of-thumb minimum of 5 -- the pre-registration guard in the script would
have aborted rather than silently proceeding if this were not true).

**Pearson chi-square statistic = 10.2195, df=7, p-value = 0.176471.**
Total variation distance (observed vs. exact) = 0.012207. N = 10,000.

**RESULT: p = 0.176471 >= alpha = 0.01 -> PASS.**

The real `thrml_backend.sample` (== `demo.lattice_app.thrml_sample`), run at
the live app's own `n_warmup`/`steps_per_sample` constants, produces a
stationary distribution statistically indistinguishable from the
independent oracle's exact Boltzmann distribution, on an instance
constructed specifically to have no symmetry that could hide a systematic
error.

## Findings

None. The pre-registered criterion passed on its first and only run, with
no parameter tuning after the fact (per the plan's explicit instruction,
and confirmed by this file's own account of the run being singular).

### What was tried and did not turn up a finding

- The chi-square rule-of-thumb validity guard (expected count of the
  rarest state `>= 5`) was checked and passed *before* the sampler was
  run, per the pre-registration -- had it failed, the script is written to
  abort with `SystemExit` rather than silently proceeding with an invalid
  approximation and a possibly-misleading p-value. It did not fire; N=10,000
  was sufficient on the first attempt.
- Total variation distance (0.0122) was computed alongside the chi-square
  test as a second, complementary summary (not itself the pre-registered
  criterion, but a sanity cross-check with a directly interpretable scale)
  -- consistent with the chi-square result, no disagreement between the two
  summaries. No finding.
- Considered whether reusing R3's own asymmetric instance (rather than
  building a fresh one for R15) could bias this test toward passing (e.g.
  if that instance happened to be unusually easy for the sampler): the
  instance has no symmetry, a non-bipartite 3-colour-chromatic structure,
  and a non-trivial coupling pattern (weights spanning both signs and three
  different magnitudes) -- nothing about its construction favours the
  sampler; it was chosen for R3's sign-flip test on different grounds
  (asymmetry to catch a double-sign-flip bug) before this section ever ran.
  No finding.
